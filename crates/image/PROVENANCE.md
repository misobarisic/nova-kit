# Shared Reader image codec

`src/avif.rs` was moved from Nova Reader revision
[`e2aba25f3f6d1be02fdc4117d902556bcc344d8e`](https://github.com/misobarisic/nova-reader/tree/e2aba25f3f6d1be02fdc4117d902556bcc344d8e),
`crates/reader-engine/src/avif.rs`. The actual metadata budgets, still-frame
admission, preallocation checks, CICP/plane conversion, alpha handling and
malformed-input regressions are preserved. Visibility and the app-owned display
integration tests are the only decoder adaptations. Reader keeps its own
display/window integration tests and delegates codec operations here.

`encode_avif` relocates the actual AVIF branch of that revision's
`src/reader_export.rs::encode_rgba`: ravif 0.13.0, eight-bit output, caller
quality, alpha quality 100, unassociated alpha, one thread and speed 8.
This is lossy encoding at every quality, including 100: rav1e 0.8.1 explicitly
does not implement lossless AV1. `tests/encode.rs` verifies changed decoded
pixels for both the production path and the quality-100/RGB workaround.
`DecodeLimits` and `PageDimensions` retain Reader's exact shape/defaults.
Encoding checks the admitted RGBA dimensions/bytes and encoded output cap;
ravif's transient working memory is additional, as in Reader. Decoder admission
also accounts for padded frame planes/parser copies before allocating a frame.
The adapter supports eight-bit still AVIF images, including alpha, and rejects
animation, unsupported transforms and higher bit depths explicitly.

The independent 349-byte `tests/fixtures/tiny.avif` and adapter attribution are
retained in [AVIF-NOTICE.txt](AVIF-NOTICE.txt). The static
`reader-legacy-rgba.avif` fixture was generated by compiling the actual former
Reader encoder block, retained in `tests/fixtures/legacy-encoder.rs.txt`, with
its documented 32×24 RGBA pattern and quality 73. Its SHA-256 is
`d34250b269c0efc07883bdd3bcbd42b00a4ad5c5c132e4f8754435ab6247e0af`.
Tests require byte-identical shared encoder output, plus native dimensions,
color/alpha tolerance and distinct real quality output.

`../../vendor/ferri-pdf-rav1d` is Reader's complete patched published 1.1.2
package, relocated unchanged: 176 files, including COPYING, upstream metadata
and PATCHES.md. The aggregate SHA-256 over sorted relative UTF-8 filenames,
NUL, and each file's binary SHA-256 is
`0120c0d94193c7b5b637b0756c159596912387117496e23522b8395342af0f6e`.
Its original published archive checksum, fork commit, hardening and two stable
ARM/RISC-V attribute predicates remain documented in its PATCHES.md.
Kit uses a direct path dependency with default features disabled and only
`bitdepth_8`; assembly and native platform codec libraries are not enabled.

Verification:

```sh
cargo test --locked -p nova-image
cargo test --locked -p nova-image avif::tests::malformed_fixture_does_not_abort_decoder_process -- --ignored --exact
cargo check --locked -p nova-image --target armv7-linux-androideabi
```

The leaf ARMv7 check uses stable Rust and the installed target standard library;
it does not require an Android NDK, nightly Rust or bootstrap flags.


## JPEG XL

`src/jxl.rs` moves the actual Reader v0.1.17 decoder from commit
`59b5000695f7b280ee22a1dd63dc1e76195c5b39`, retaining its dimension/encoded/grid
limits, direct RGBA row conversion and auxiliary-box skipping. The existing
synthetic RGB/alpha and boxed-metadata tests/fixtures move unchanged with it.
The public magic probe is renamed `is_jpeg_xl`; Reader retains a thin adapter.
Decoding uses jxl-oxide 0.12.6 (MIT OR Apache-2.0), with Rayon and native CMS off.
Custom ICC, previews, animation, CMYK and extra channels remain unsupported.

`src/jxl_encode.rs` adds eight-bit RGBA encoding using jixel 0.5.2
(BSD-3-Clause OR Apache-2.0), a Rust implementation derived from libjxl-tiny.
All default Cargo features are disabled: no platform SIMD, splines or extra-slow
perceptual-metric dependencies. Configuration explicitly selects one thread,
Fast effort, lossless alpha and preserved invisible RGB. `JxlEncoding` separates
true lossless encoding from lossy quality (including lossy quality 100).
Dimension/pixel/RGBA input and final output caps are enforced before/after the
codec; encoder working memory is additional. Local interop tests validate native
pixels, alpha, quality behavior and malformed/low-limit input, not comparative
compression ratios or device performance against libjxl.


`transcode_jpeg_to_jxl` uses jixel's reversible JPEG coefficient path and retains
JPEG reconstruction boxes. It checks encoded size and dimensions before
transcoding and admits only the shared still-image decoder's supported subset.
The cache's opt-in `jxl_lossless_jpeg` defaults to false and applies only to JPEG
inputs that do not require resizing. Unsupported JPEGs and other images use the
selected normal encoder/quality. The false recipe omits the new field, preserving
existing keys. Tests reconstruct the original JPEG byte for byte using jxl-oxide.
